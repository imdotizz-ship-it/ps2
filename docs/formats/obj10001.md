# Formatos `OBJ10001` e `TEX10001` (MotoGP 4 PS2, Namco)

Modelos e texturas dentro dos arquivos do `MOTOGP.DAT` (por exemplo
`bike_motogp_for_46`: um bloco `OBJ10001` seguido de um `TEX10001`). Código:
`tools/mgp4to08/mgp4obj.py`, `mgp4mesh.py`, `mgp4tex.py`.

Todos os inteiros são little-endian.

## Cabeçalho comum

`OBJ10001` ou `TEX10001` (8 bytes), seguido de um bloco marcado por
`FC FF` … `FE FF`. Em +0x20 fica o tamanho do cabeçalho e em +0x24 o
**ID base** (u32).

## Texturas (`TEX10001`)

Depois do cabeçalho, as texturas aparecem em sequência:

| Offset | Conteúdo |
| ------ | -------- |
| +0x00 | u16 largura, u16 altura, u16 `tw`, u16 `th` (retângulo de envio em PSMCT32) |
| +0x20 | paleta: 16 (4 bits) ou 256 (8 bits) cores RGBA, alfa 0..0x80; a de 256 em ordem CSM1 |
| depois | pixels, `tw * th * 4` bytes |

Os pixels foram gravados como PSMCT32 e precisam ser desembaralhados: grava-se
o retângulo `tw x th` em PSMCT32 com largura de buffer `tw/64` e lê-se a
imagem em PSMT4/PSMT8 com largura de buffer `largura/64` (mínimo 2).

### IDs

Cada textura tem um ID de 16 bits. A primeira usa o ID base. A lista de u16
em +0x28 do cabeçalho dá o salto até a próxima:

- `w & 0x8000`: próxima = atual + 1 (os 15 bits baixos são o formato);
- `w` com `0xA0` no byte alto: prefixo, o byte baixo é o salto da próxima entrada;
- sem esses bits: byte baixo = formato, byte alto = salto;
- `0xFFFF` encerra; `FC FF` … `FE FF` é um bloco aninhado (ignorado).

Os IDs `0x2711`–`0x2729` são texturas comuns de corrida que ficam em
`CourseCommon` (branco, vidro, pinças Brembo, painel etc.).

## Modelos (`OBJ10001`)

Cada malha é um pacote DMA `ret` (tag `0x6000xxxx`) com comandos VIF,
precedido de 0x20 bytes: esfera envolvente (4 f32: centro e raio) e até 8 IDs
de textura (u16, `0xFFFF` = vazio).

Dentro do pacote, cada lote (terminado por `MSCAL`) é **uma tira de
triângulos**:

| Unpack | Conteúdo |
| ------ | -------- |
| V2-32 em 0 | número de vértices, índice da textura na lista do cabeçalho |
| V4-32 em 1 (STCYCL 3/2) | por vértice: `x, y, z, nx` e `u, v, ny, nz` |
| V3-8 em 3 | cor RGB por vértice (0x80 = 1.0), usada como luz pré-calculada |

O **bit 0 de `nx`** é o bit ADC do PS2: um vértice marcado não fecha
triângulo (reinício da tira). As cópias espelhadas das peças diferem só nesse
bit.

Unidades em milímetros, Y para cima, frente em -Z. Eixos das rodas da moto
#46: traseiro (0, 316, 724), dianteiro (0, 302, -725). Para o MotoGP 08:
`(x, y, z) -> (-x, y, 724 - z) / 1000`.

### Peças de uma moto

Os arquivos não têm nomes de peças. A classificação usa a esfera:

- carenagem/quadro/motor/escapamento: centro com y > 300 e raio < 1000, em
  dois níveis de detalhe (pares com a mesma esfera e os mesmos IDs de textura);
- para-brisa: centro com y > 950 e raio < 300;
- garfo, guidão e balança: no espaço do próprio pivô (centro com y < 300);
- moto inteira de baixo detalhe: raio > 1000 (inclui rodas hexagonais);
- sombras: textura `0x2713`;
- os últimos pacotes (STCYCL 1/1, só posições) são volumes de colisão/sombra.
